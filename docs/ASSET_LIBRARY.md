### Licence terms (free low-poly tier)

- **Mesh files (GLB, FBX, USD, OBJ):** user's choice of
  1. **CC BY 4.0** — commercial use, redistribution allowed, credit required:
     `"<Name> by Polyfork (<page URL>), CC BY 4.0"`; or
  2. **Polyfork licence** — no credit required, **no redistribution** of the raw files.
- **`.mjs` source and HD editions:** Polyfork licence only (no redistribution).
- **Hotlinking:** "Linking to the free models is not redistribution." Products may fetch free GLBs
  from the CDN for end users **per use** (no bulk scraping), should send a product-identifying
  `User-Agent`, and must back off on HTTP 429. **Caching/mirroring/proxying the files yourself
  requires a separate platform licence** (`/platform`).

## 2. Integration decision (ADR-0008)

1. **Live asset browser (free tier only):** search and list via the public REST API, show
   previews, load GLBs **directly from the CDN** with `GLTFLoader` when the user adds an asset. No
   API key, no proxy. We use **GLB only** (never `.mjs`, never HD).
2. **No persistent mirroring:** the app does not store polyfork GLBs in IndexedDB or a service-worker
   cache (normal HTTP caching by the browser is fine). Saved scenes store the asset **id and URL**,
   not the bytes.
3. **Licence path: CC BY 4.0.** Every polyfork asset added to a scene creates an `AssetRef` with
   name, page URL and licence; the app shows a credits panel; exports embed credits in glTF
   `asset.extras` / node `extras` and a `CREDITS.txt` in bundle exports. (Exported baked scenes
   contain the meshes → redistribution by the user, permitted under CC BY with credit.)
4. **Nothing committed:** polyfork meshes are generated by scripts; committing them to a public
   repository could be seen as redistribution. **Never commit polyfork files** (also not as test
   fixtures). The showcase scene references them by CDN URL (loaded live); automated tests use
   procedurally generated primitives and our own small glTF fixtures only.
5. **Politeness:** request rate limited client-side (e.g. ≤ 4 concurrent, debounce search),
   exponential back-off on 429, clear UI error. Browsers forbid setting `User-Agent` from `fetch`;
   identification through the browser's `Referer`/`Origin` is accepted (project decision
   2026-11-20).
6. **Fallback / alternative:** a generic **GLTF/GLB importer** (file picker, drag-and-drop, URL)
   for any compatible assets, plus built-in **primitives** (box, plane, sphere, cylinder, cone,
   torus, stairs, arch). The app works fully offline with primitives and local files.

## 3. Consequences for the baker (important)

polyfork assets carry their colour in **vertex colours** with a single shared material. Upstream
lightbaker only has **per-material albedo**. Therefore:

- The bake scene must support **per-vertex (or per-triangle) albedo** (`colors` array in scene v2;
  for flat-shaded assets the colour is constant per triangle). GPU: a per-triangle albedo entry
  next to the per-triangle UVs; `bounced()` uses it instead of the material albedo when present.
  Tracked as **REQ-LGT-10** and part of Phase 4 (minimal: per-triangle average of vertex colours).
- glTF vertex colours (`COLOR_0`) are linear; multiply with `baseColorFactor` (also linear).
- Albedo clamp (≤ 0.9) and colour-space rules from [LIGHTING_MODEL.md](LIGHTING_MODEL.md) apply.
- Runtime: three.js materials keep `vertexColors = true`; the lightmap multiplies by them via the
  normal material pipeline (no change to the rendering rules).

## 4. Import pipeline (GLB → editor → baker)

1. `GLTFLoader` (+ `KHR_mesh_quantization`, Draco/meshopt decoders if present) → Three.js scene.
2. Normalise: apply node transforms to world space for baking, keep hierarchy for the editor;
   convert to indexed `BufferGeometry`; ensure normals; keep `uv` (texture) untouched.
3. Map materials: `color`/`map` → albedo (average of texture for the baker if textured; documented
   approximation), `emissive`·`emissiveIntensity` → emission, `transparent/opacity` → opacity,
   `side === DoubleSide` → `doubleSided`, `COLOR_0` → vertex albedo.
4. Material groups (`geometry.groups`) → per-triangle material ids.
5. Record `AssetRef` (source, URL, licence, author).
