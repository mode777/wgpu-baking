this file corrected) in the phase that introduces it. Commands marked *(P1)*, *(P2)*, … become valid
at that phase.

## One-time setup

```powershell
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version <pinned>      # or: cargo install wasm-pack
corepack enable
pnpm install                                           # (P2) at the repository root
```

## Native engine

```powershell
cargo build --release -p lightbaker-cli                                    # (P1)
cargo run --release -p lightbaker-cli -- scene.lbscene --out baked/ --cache .lbcache/   # (P1, upstream usage)
cargo test -p lightbaker                                                   # GPU tests skip without an adapter (see CI env vars below)
cargo run --release -p lightbaker-cli -- test-scenes/upstream-basic/upstream-basic.lbscene --out baked/ --check   # bake a test scene and check its expect.json
# software adapters are refused unless --allow-software-adapter (or LIGHTBAKER_ALLOW_SOFTWARE_ADAPTER=1)
cargo run --release -p lightbaker --example export-upstream-basic -- --bake # regenerate test-scenes/upstream-basic (+ reference values)
cargo run --release -p lightbaker --example baseline -- --json out.json  # phase-report measurements (stages, transfers)
```

## WASM engine

Features of `lightbaker` (ADR-0003): `native` (default: rayon, pollster, zstd, `FsStore` file cache, all
native wgpu backends) and `web` (WebGPU only, sequential CPU stages, `MemoryStore`, KTX2 without zstd).
GPU integration tests and examples require `native`.

```powershell
cargo build -p lightbaker --target wasm32-unknown-unknown --no-default-features --features web   # verified P2.1
cargo test -p lightbaker --no-default-features --features web --lib                              # web-feature unit tests on the host
wasm-pack build crates/lightbaker-web --target web --release                                     # verified P2.4 → crates/lightbaker-web/pkg (~1.1 MB wasm)
wasm-pack test --node crates/lightbaker-web                                                      # verified P2.4: bridge tests in Node (no WebGPU)
cargo test -p lightbaker-web                                                                     # host unit tests (config overrides, error kinds)
```

Versions (P2.4): `wasm-bindgen` 0.2.130 (from `Cargo.lock`; wasm-pack 0.15.1 installs the matching
`wasm-bindgen` CLI automatically), Node ≥ 22 for `wasm-pack test --node` (needs the global `navigator`).
`wasm-opt` is disabled in the crate's wasm-pack profile (no download needed).

## App

```powershell
pnpm -C app dev          # (P2) Vite dev server; open the printed URL in Chrome/Edge
pnpm -C app build        # (P2) production build in app/dist
pnpm -C app test         # (P2) Vitest
pnpm -C app e2e          # (P2) small Playwright set (Chrome with WebGPU enabled), see TESTING.md
```

WebGPU in automated Chrome needs flags. The Playwright config (P2) uses the set proven in three.js'
CI: `--enable-unsafe-webgpu --enable-features=Vulkan --disable-vulkan-surface
--ignore-gpu-blocklist --disable-gpu-watchdog --no-sandbox`, headed under `xvfb-run` on Linux. On a
machine without a hardware GPU this uses a software adapter, which the app only accepts with
`allowFallbackAdapter: true`; results are labelled.

## Running GPU tests locally on a software adapter (Linux)

```bash
sudo apt-get install -y mesa-vulkan-drivers xvfb          # lavapipe (software Vulkan)
LIGHTBAKER_REQUIRE_GPU=1 LIGHTBAKER_ALLOW_SOFTWARE_ADAPTER=1 cargo test -p lightbaker
xvfb-run -a pnpm -C app e2e
```

## Reproducibility

- `Cargo.lock` and `pnpm-lock.yaml` are committed; `rust-toolchain.toml` pins the compiler.
- `wasm-bindgen` crate and CLI versions must match exactly (pinned together).
- xatlas: native vendors `jpcy/xatlas` at `f700c77` with its licence
  (`crates/lightbaker-uv/vendor/xatlas`); the web uses `xatlas-wasm` pinned to an exact version
  built from the same commit (ADR-0006).

## Continuous integration (GitHub Actions, ADR-0009)

Standard GitHub-hosted runners only; GPU work runs on software adapters (Mesa lavapipe).

| Job | Runner | Steps |
|---|---|---|
| `rust-native` | ubuntu-latest, windows-latest | fmt/clippy (new crates), build, unit tests |
| `rust-gpu` | ubuntu-latest | `apt-get install mesa-vulkan-drivers`; GPU integration tests with `LIGHTBAKER_REQUIRE_GPU=1`, `LIGHTBAKER_ALLOW_SOFTWARE_ADAPTER=1` |
| `wasm` | ubuntu-latest | wasm32 build, `wasm-pack build`, `wasm-bindgen-test` (Node, non-GPU) |
| `web` | ubuntu-latest | `mesa-vulkan-drivers xvfb`; pnpm install, typecheck, Vitest, app build, `xvfb-run -a pnpm -C app e2e` |
| `gpu-perf` (optional) | GPU larger runner / self-hosted, `workflow_dispatch` | real-GPU timings for phase reports |

Each job should stay under ~10 minutes. Performance numbers from software adapters are not
meaningful; real-GPU measurements go into the phase reports.

Workflow: [.github/workflows/ci.yml](../.github/workflows/ci.yml). Status: `rust-native`, `rust-gpu` (P1.3)
and `wasm` (P2.3: wasm32 build of `lightbaker` with `web`, web-feature unit tests, and a guard that fails
if `pollster`, `rayon` or `zstd` enter the web dependency tree) exist; `wasm-pack`/`wasm-bindgen-test`
join `wasm` with P2.4, `web` arrives with P2.6. New crates are added to the
`CLIPPY_CRATES` list there to be linted with `-D warnings`.

GPU test environment variables (read by the test helper in `crates/lightbaker/tests/bake.rs`):

| Variable | Effect |
|---|---|
| `LIGHTBAKER_REQUIRE_GPU=1` | no usable adapter **fails** the test instead of skipping it |
| `LIGHTBAKER_ALLOW_SOFTWARE_ADAPTER=1` | a software adapter (CPU device type; llvmpipe/lavapipe, SwiftShader, WARP/"Microsoft Basic Render Driver") may be used; output is labelled `[SOFTWARE ADAPTER …]` |

Reproducing CI locally without Docker/WSL (Windows): run the `rust-native` steps verbatim
(`cargo build --workspace --locked`, `cargo test --workspace --locked`) and the `rust-gpu` step
against the local hardware GPU with `$env:LIGHTBAKER_REQUIRE_GPU='1'; cargo test -p lightbaker --release`.
The Linux/lavapipe jobs are verified on GitHub.
