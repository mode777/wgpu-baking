# Testing strategy

Requirements covered: REQ-ENG-04, REQ-ENG-05, plus the verification column of
[REQUIREMENTS.md](REQUIREMENTS.md).

## Principles

- **Prove light transport with numbers, not screenshots.** Every lighting feature has a test that
  measures irradiance at known points against an analytic expectation or a ratio (upstream's
  `tests/bake.rs` style: "the shadow side is darker than the lit side", "the ground near the red
  wall is redder than far from it").
- **Determinism.** The same scene and settings produce the same bytes (upstream guarantees this
  for `.lbake`). Tests may compare exact outputs between runs and between cache/no-cache.
- **Native first, browser second.** Algorithmic tests run natively (`cargo test`), the same scenes
  then run in the browser to prove parity.
- **No GPU → skip locally, fail in CI.** Upstream skips GPU tests without an adapter; CI sets
  `LIGHTBAKER_REQUIRE_GPU=1` so a missing adapter fails the job. CI uses software adapters
  (Mesa lavapipe) explicitly allowed with `LIGHTBAKER_ALLOW_SOFTWARE_ADAPTER=1` (ADR-0009). Without
  that opt-in a software adapter counts as no adapter; with it, test output labels the adapter as
  software. Detection and refusal live in the engine (`lightbaker::gpu::{is_software_adapter, admit}`,
  unit-tested in `crates/lightbaker/src/gpu/adapter.rs`): `Gpu::open` refuses a software adapter unless
  `GpuOptions::allow_software`, which the test helper, the CLI (`--allow-software-adapter`) and the
  `baseline` example set from the env var.
- **Few, cheap end-to-end tests.** Behaviour is proven at the lowest possible layer (Rust, WASM,
  Vitest with mocked workers). Browser e2e tests are limited to the budget below.

## Test layers

| Layer | Tooling | Location | Runs in CI |
|---|---|---|---|
| Rust unit | `cargo test` | `crates/*/src` (`#[cfg(test)]`) | `rust-native` |
| Rust GPU integration | `cargo test` (wgpu native) | `crates/lightbaker/tests/` | `rust-gpu` (lavapipe) |
| WASM unit | `wasm-bindgen-test` (Node, no GPU) | `crates/lightbaker-web/tests/` | `wasm` |
| TS unit / component | Vitest (worker protocol and stores tested with mocks) | `js/`, `app/src/**/*.test.ts` | `web` |
| Browser e2e | Playwright, Chrome with WebGPU flags | `app/e2e/` | `web` (lavapipe, budget below) |
| Visual review | images from fixed cameras, compared by eye/tolerance | `docs/reports/` | **no** (manual, phase reports) |

### E2E budget

At most **three Playwright specs**, together under ~5 minutes on lavapipe, CI-sized scenes only:

| Spec | From | Covers |
|---|---|---|
| `bake-poc.spec.ts` | P2 | bake `upstream-basic` (CI profile) in the worker; metrics vs `expect.json`; cancel mid-bake then rebake |
| `no-webgpu.spec.ts` | P2 | capability message when WebGPU is unavailable (cheap, no bake) |
| `editor-smoke.spec.ts` | P5 | add primitive + point light → bake (CI profile) → toggle baked/unbaked → move light → rebake without reload |

Everything else (import round trips, UI panels, export, error mapping, device-loss handling with a
mocked `GPUDevice.lost`) is covered by Vitest/Rust tests. Adding a fourth spec needs a reason in the
OpenSpec change.

Status (P2.6): `bake-poc.spec.ts` and `no-webgpu.spec.ts` exist (`app/e2e/`, `pnpm -C app e2e`), run in
CI's `web` job on a software adapter (Chromium offers only SwiftShader on the runner, ADR-0009). `bake-poc` uses the page's `profile=ci` (fewer rays; all 19 checks still
hold on hardware and on SwiftShader) and asserts the checks, the adapter label and cancel →
rebake. `no-webgpu` loads the page in an **insecure context** (plain http from a non-localhost name
mapped to 127.0.0.1), where browsers do not expose `navigator.gpu` — a real absence, no test hook in
the app. Switches: `E2E_CHANNEL=chrome|msedge` (installed browser), `E2E_HEADED=1` (CI, under
`xvfb-run`), `E2E_ALLOW_FALLBACK=1` (software adapter opt-in; the spec then expects the SOFTWARE ADAPTER
label), `E2E_BROWSER_ARGS` (extra flags, e.g. `--use-webgpu-adapter=swiftshader`).

## Deterministic test scenes (`test-scenes/`)

Each scene is a small `.lbscene` (generated by a script, committed) with a `expect.json` listing
probe points and assertions. Scenes are built so that each one isolates one feature.

Present (P1.4): `test-scenes/upstream-basic/` — regenerate with
`cargo run -p lightbaker --release --example export-upstream-basic [-- --bake]` (`--bake` re-records the
reference values on this machine's GPU). `cargo test -p lightbaker` checks that the committed scene equals
the generator's output, bakes it twice (identical bytes) and evaluates its checks;
`lightbaker <scene> --check` does the same from the CLI.

### `expect.json` format

Parsed and evaluated by `lightbaker::expect` (unknown fields are rejected):

```jsonc
{
  "scene": "upstream-basic.lbscene",          // beside expect.json
  "description": "…",
  "probes": [                                  // where the bake is sampled
    { "name": "near", "map": "indirect", "mesh": 0, "point": [38.5, 0, 40] }
  ],
  "checks": [                                  // a op b·scale + offset, op is "<" or ">"
    { "name": "red wall bleeds onto the ground", "a": "near[0]/near[1]", "op": ">", "b": "far[0]/far[1]", "scale": 1.15 }
  ],
  "reference": { "adapter": "…", "bakerVersion": 11, "values": { "near": [0.1, 0.04, 0.03, 0.17] } }
}
```

- `map` and the 4 components of a probe's value: `direct` = `[sun field, AO, 0, 0]`; `indirect` =
  `[r, g, b, r+g+b]` (irradiance, linear RGB, at the downscaled indirect atlas); `volume` = the grid probe
  at or below the point, `[L0 r, L0 g, L0 b, sun visibility]`.
- `point` must lie on a triangle of `mesh` (within 1 mm of its plane); otherwise evaluation fails naming
  the probe. The texel is found through that triangle's chart.
- Operands: a number, `name[i]`, or `name[i]/name[j]`; `scale` defaults to 1, `offset` to 0.
- `reference` is informative: values from a native bake on a named adapter, used to compare other
  adapters (e.g. the browser, Phase 2). Checks, not reference values, decide pass/fail.

| Scene | Purpose | Key assertions |
|---|---|---|
| `upstream-basic` | upstream `tests/bake.rs` scene (ground, box, red wall, strip) | upstream assertions, now also in the browser |
| `furnace` | closed box, uniform albedo `ρ`, uniform emission `Le` | radiance after `k` bounces = `Le·(1−ρ^(k+1))/(1−ρ)` within 2 %; never above `Le/(1−ρ)` |
| `point-falloff` | plane + one point light, no GI | `E(d)` follows `I·cosθ/d²·w(d,r)` within 3 % |
| `spot-cone` | plane + spotlight | inside inner cone = point value; outside outer cone = 0; smoothstep between |
| `area-rect` | plane under a rect light | matches the analytic form factor of a parallel rectangle within 3 % |
| `emissive-bleed` (Test 2) | dark room, one green emissive cube | floor near the cube: G/R ratio > 3; emission only via GI |
| `color-bleed` (Test 1) | RGB walls next to white walls | white wall chroma shifts towards the neighbouring wall colour by a set margin |
| `bounces` (Test 4) | enclosed coloured room, sun through a window | mean indirect monotonically increases with bounces and converges (Δ < 2 % from 4→5) |
| `leak` | thin wall between lit and dark rooms, shared floor | dark side stays below a threshold at every interpolation mode |
| `thin-double-sided` | foliage cards with `doubleSided` | no black texels; validity codes as expected |
| `uv-multi-material` | mesh with 3 material groups and texture UVs | `uv` unchanged; `uv1` valid; groups preserved |
| `uv-multi-page` | many objects at high density | > 1 page, no chart crosses a page |

## UV generation tests (`lightbaker-uv`)

- No two charts overlap in texel space (rasterise all charts, count conflicts = 0).
- Every chart has ≥ `padding` empty texels to any other chart.
- No triangle with zero or negative UV area (flips) unless its 3D area is zero.
- Texel density within ±20 % of the requested `texelsPerMeter` per chart (excluding tiny charts).
- Fragmentation metrics: charts per 1 000 triangles and atlas utilisation stay within thresholds
  recorded per test mesh (regression guard).
- `xref` mapping reproduces original positions/normals/texture UVs exactly.
- Native and web unwraps are **equivalent** (same chart count, all validity checks pass, UVs within
  a small epsilon); each target is bit-deterministic with itself (ADR-0006: different compilers).

Present (P3.5–P3.6): `cargo test -p lightbaker-uv` — `tests/validity.rs` (quad sizing, 3-material box,
`upstream-basic` meshes, UV sphere, 16 k-triangle torus knot twice: identical, bad input) and
`tests/equivalence.rs`; `app/test/xatlas.test.ts` — the same checks over `xatlas-wasm` in Node, and the
equivalence scene through the bridge (`initSync`) + `xatlas-wasm`. **Equivalence fixture**
`test-scenes/uv-equivalence/` (quad, box, sphere, torus knot at 16 texels/m; regenerate with
`cargo run -p lightbaker-uv --example export-uv-equivalence`): `native.json` is the native unwrap; native and
web must match its tile sizes, chart counts, `xref` and indices exactly and its UVs within 0.01 texel
(measured: wasm vs MSVC ≤ 1.1·10⁻⁴ texel). The browser e2e unwraps `upstream-basic` through the bridge.
Overlap/padding rasterisation checks come with P3.9.

All deterministic scenes run natively in CI (`rust-gpu`, CI bake profile). In the browser, CI runs
only `upstream-basic` (e2e budget); browser parity for the other scenes is checked in phase reports
on real GPUs.

## Lighting/bake tests

- Rust ↔ WGSL struct layout tests (size and field offsets).
- Determinism: bake twice → identical bytes; bake with warm cache → identical bytes.
- Cancellation: cancel mid-bake → `cancelled` event within one batch; next bake succeeds
  (Rust test with a cancel hook; one browser check in `bake-poc.spec.ts`). Implemented:
  `tests/scenes.rs::progress_and_cancel` (exactly one GPU batch dispatched before the stop; the next bake
  is byte-identical) and `cancelled_bake_leaves_the_store_unchanged` (cancel during bounce 1 → the
  `MemoryStore` stays empty).
- Device loss: native test drops the device mid-bake; worker/bridge error mapping tested in Vitest
  with a mocked `GPUDevice.lost`; real `device.destroy()` checked manually in the Phase 2 report.
  Implemented: `tests/scenes.rs::device_lost_mid_bake` (`Gpu::destroy()` → `GpuError::DeviceLost`, the
  lost receiver resolves), `app/test/service.test.ts` (loss outside/during a bake, reported once,
  `BakerService.recreate()` → a new worker bakes), and `app/scripts/hw-check.mjs --lose-device` (real
  `device.destroy()` via the page's `?debug=1` button → "device lost" → Recreate → bake passes).
- Limits: scene needing more than `maxStorageBufferBindingSize` → split or `limit-exceeded`,
  never a crash.

## Browser / app tests

- Capability check: `no-webgpu.spec.ts`.
- Calibration (LIGHTING_MODEL.md §8): a plane with constant baked `E` renders `ρ·E/π` before tone
  mapping. Pixel read-back is a step of `editor-smoke.spec.ts` (WebGPU backend); the WebGL backend
  is checked manually in the Phase 5 report.
- Editor flow: `editor-smoke.spec.ts` (see the e2e budget).
- glTF import round trip (import → export GLB → re-import → geometry, materials, `uv`, `uv1`
  equal): Vitest in Node with the three.js loaders/exporters, no browser.

## Visual review (manual)

- Phase reports include renders from fixed cameras at fixed resolution on real GPUs, compared
  against the previous phase's images with a tolerance (per-pixel ΔE, share of differing pixels).
- Not part of CI: GPUs/software adapters differ in floating-point details; the **metrics** above
  are the automated guard. Lighting changes that alter metrics bump `BAKER_VERSION` and update
  `expect.json` in a reviewed change.
